Los ocho nodos que resuelven el noventa por ciento

La clase pasada contaste ítems sin nombrar casi ningún nodo. Hoy vienen los nombres, y vienen atados a un caso que no se puede resolver con una planilla: un bot de mensajería que consulta InfoLeg, un sitio que no tiene API ni RSS. Solo HTML.

Retomamos

La clase 4 se fue debiendo tres cosas

No son detalles sueltos: las tres se pagan hoy, y las tres se pagan con nodos que ya viste pasar sin que nadie te dijera cómo se llamaban.

Un nodo no se elige porque exista. Se elige porque el algoritmo que escribiste antes lo pide.
El pasillo

«Y otra vez alguien pegó mal el número»

Un estudio contable de veinte personas. La socia lo cuenta como lo cuenta un dueño de proceso: en desorden, sin pasos numerados, con la bronca al frente.

Cada vez que sale algo, alguien tiene que entrar a InfoLeg, buscar la norma, copiar el link y pegarlo en el grupo. Y la mitad de las veces pega mal el número, o pega la modificatoria en vez de la ley. Después el que la usa se entera tarde.
Lo que se escucha

Cinco frases, cinco decisiones

  • «cada vez que sale algo» — todavía no sabemos si el disparador es una fecha, un aviso o una persona preguntando.
  • «alguien tiene que entrar» — hay un humano haciendo de puente entre dos sistemas.
  • «buscar la norma» — hay una consulta con parámetros: tipo y número.
  • «copiar el link» — el resultado que importa es una URL estable, no el texto entero.
  • «pega la modificatoria» — hay una regla de negocio escondida: no toda norma que menciona el número es la que buscan.

El disparador que elegimos es el más chico de todos: alguien le escribe al bot. No resuelve el aviso automático, y esa es la parte que dejamos abierta a propósito para la clase 6.

La pregunta previa

Antes de escribir un selector, buscá si el dato ya está publicado

InfoLeg no tiene API ni RSS. Esa es la premisa, y es cierta. Pero la premisa completa es otra: el organismo publica la misma base en formato abierto, y eso cambia el diseño entero.

Buscar

El índice abierto

El Ministerio de Justicia publica la Base InfoLeg de Normativa Nacional en el portal de datos abiertos, con tipo, número, fecha, título y el id de InfoLeg de cada norma. Estructurado, con actualización diaria, sin un solo selector CSS.

Leer

El HTML de InfoLeg

El texto de la norma sigue viviendo en una página web pensada para que la lea una persona. Ahí sí hace falta pedir el HTML y extraer lo que interesa. Es el único tramo donde scrapeamos.

Decidir

El criterio

Scrapear es lo último que se prueba, no lo primero. Un dato publicado es un contrato; una página es una casualidad que hoy funciona. Cuando existan los dos, el flujo usa el dato y deja la página para lo que no está publicado.

Base InfoLeg de Normativa Nacional en datos.gob.ar y datos.jus.gob.ar: muestreo en CSV y base completa en ZIP, con actualización diaria. Consultado el 2 de septiembre de 2026; el dataset figuraba actualizado al 1 de septiembre de 2026. Verificá la fecha antes de usarlo en producción: es lo primero que se desactualiza.

Caso 05 · 14 nodos · una ejecución por pedido

El bot que lee InfoLeg

CUANDO llega un mensaje al bot:
    leer { texto, chat }
    entender qué pidió: tipo de norma y número

    SI no se entiende qué norma es:
        responder "decime tipo y número: ley 27742"
        FIN

    buscar la norma y quedarse con su id de InfoLeg

    con el id, calcular la carpeta del anexo y pedir el texto
    extraer el título y el arranque del articulado

    SEGÚN tipo:
        ley:      citar "Ley 27.742 (B.O. 08/07/2024)"
        decreto:  citar "Decreto 70/2023"
        otro:     citar tal como vino

    juntar la ficha con el texto en una sola respuesta
    responder por el mismo chat, con el link a InfoLeg
FIN

Ocho verbos. Cada uno se va a convertir en uno de los ocho nodos, y en el mismo orden. Esa correspondencia no es una casualidad didáctica: es la razón por la que escribimos el algoritmo primero.

El catálogo

Ocho nodos, y dos invitados que se ganaron el lugar

Tocá cada uno. Lo que importa de un nodo no es dónde está en el menú: es qué recibe, qué entrega, si cambia la cantidad de ítems y cuándo no hay que usarlo.

Los dos invitados no están en el título de la clase y aparecen igual, cada uno por una razón concreta del caso: el HTML porque la web no devuelve JSON, y el Summarize porque salda la deuda que dejó la clase 4. El diez por ciento restante de los flujos empieza exactamente acá.

La deuda de la cardinalidad

Los tres cambios de cantidad, ahora con nombre propio

La clase 4 te enseñó a reconocer la forma en el panel de salida: entraron cuarenta y salieron cuarenta, entraron cuarenta y salió uno, entró uno y salieron cuarenta. Estos son los nodos que producen cada una de las tres.

El IF y el Switch no están en esta lista y conviene decir por qué: no cambian la cantidad de ítems, cambian por dónde siguen. Cuarenta ítems que entran a un IF salen cuarenta, repartidos entre dos puertas. Confundir repartir con filtrar es el error que más tiempo cuesta encontrar.

La deuda del código

La línea de JavaScript de la clase 4 era un nodo

El resumen para Valentina se armaba con una expresión escondida adentro del texto del mensaje. Funcionaba. Y se puede hacer sin escribir una sola línea.

Clase 4 · con código

Una expresión adentro del mensaje

{{ $json.pedidos.map(p =>
     '- ' + p.Cliente + ': $' + p.Monto
   ).join('\n') }}

Anda. Pero el día que se rompe, se rompe adentro de un campo de texto de un nodo de Telegram, que es el último lugar donde a alguien se le ocurre mirar. Y no lo puede tocar quien no sabe JavaScript.

Clase 5 · sin código

Dos nodos, cada uno con una tarea

Edit Fields  →  linea = "- {{ $json.Cliente }}: ${{ $json.Monto }}"
                (uno entra, uno sale)

Summarize    →  concatenar "linea", separador salto de línea
                (muchos entran, uno sale)

El mismo resultado, visible en el lienzo, con el panel de salida mostrando qué pasó en cada paso. Cualquiera del equipo puede cambiar el formato de la línea sin tocar código.

El Code es el octavo nodo porque es el último, no porque sea el peor.

Y para que quede claro que no es una prohibición: en el caso de hoy el Code aparece, y aparece por una razón que ningún nodo puede cubrir. InfoLeg guarda el texto de cada norma en una carpeta que agrupa de a cinco mil ids. La Ley 27.742 tiene el id 401266, así que su texto vive en anexos/400000-404999/401266/norma.htm. Ese 400000-404999 no viene en ninguna respuesta: es una cuenta, Math.floor(id / 5000) * 5000. Eso es un nodo Code bien usado.

    La letra chica
    
El HTML no es una API, y conviene decirlo antes de festejar

    
El flujo anda. También andaba el que se rompió el mes pasado en otra oficina. Estas cinco cosas separan un truco de una automatización que se puede dejar prendida.


    


    
Nada de esto es exclusivo de InfoLeg. Es lo que hay que mirar cada vez que un flujo depende de una página pensada para que la lea una persona.

  







  

    El postre
    
Y ahora sí, el agente: elige, no hace

    
Lo que el bot de hoy hace mal es entender «che, pasame la de bases» o «el decreto de diciembre del 23». Eso es exactamente lo que un modelo hace bien, y es lo único que le vamos a dar.


    

      

        Capa de arriba · cuatro nodos
        
El agente entiende y decide

        
Recibe el mensaje en lenguaje natural, decide qué herramienta llamar y con qué parámetros, y redacta la respuesta. No sale a la web, no mira HTML, no inventa el número de una ley: si la herramienta no encuentra nada, lo dice.

        Capa de abajo · los catorce de hoy
        
Los nodos hacen

        
El mismo workflow que construiste, convertido en herramienta. Determinista, reproducible, con una sola forma de fallar y un panel donde se ve qué pasó. Dos personas que preguntan lo mismo reciben lo mismo.

      

    


    
El agente elige, los nodos hacen. Al revés cuesta más, tarda más y da respuestas distintas a la misma pregunta.
