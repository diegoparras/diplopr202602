MCP: el protocolo que conecta la IA con tus herramientas

La clase pasada un agente escribió con vos, pero a ciegas: todo lo que sabía de tu n8n se lo copiaste a mano. Hoy le abrimos la puerta. MCP es el estándar que deja que una IA lea tus sistemas y actúe sobre ellos, y n8n está de los dos lados: puede recibir a una IA que arma flujos y puede salir a usar herramientas de otros. Abrir la puerta obliga a decidir qué puede tocar quien entra.

Teoría · 1 · Apertura

¿Quién armó un flujo en un chat de IA y después lo pasó a n8n?

Elegí lo que hiciste alguna vez.

Qué es

MCP, Model Context Protocol, es un estándar de código abierto para conectar aplicaciones de IA con sistemas externos. Con MCP, aplicaciones como Claude o ChatGPT se conectan a fuentes de datos (archivos, bases de datos), a herramientas (buscadores, calculadoras) y a flujos de trabajo, para buscar información y ejecutar tareas.

MCP es como un puerto USB-C para la IA. Antes cada celular tenía su cargador; hoy un solo cable carga todo.

Teoría · 2 · Por qué ahora

Trabajamos con IA en dos mundos

1

Lo que la IA ya conoce

Desarrollamos con IA: Codex, Claude Code, VS Code, Cursor. La IA ve el código que estamos escribiendo, está adentro de nuestro proyecto. Es lo de la clase 12.

2

Lo que la IA no conoce

La base de datos, GitHub, el newsletter, el CRM, el calendario, tu n8n. Son sistemas de terceros, en la nube o en servidores remotos, fuera de nuestro proyecto.

El valor aparece cuando la IA puede leer y actuar sobre el segundo mundo: un asistente que mira tu calendario y tus notas, un agente de código que sube una web a Vercel desde GitHub, o una IA que arma un flujo en tu n8n.

Teoría · 3 · El problema antes de MCP

Cada conexión, hecha a medida

Para conectar un modelo a un sistema externo había que programar algo específico: que Codex hablara con esa herramienta, y después repetirlo para Claude Code, para Cursor, para cada una. Mové los controles y cambiá de modo.

Esto ya pasó antes. HTTP estandarizó la web; el USB, los periféricos. Faltaba un estándar para conectar la IA.

Teoría · 5 · Arquitectura

Tres participantes y un restaurante

Host

La aplicación de IA que coordina uno o varios clientes MCP. Claude Code, Codex, Claude Desktop, VS Code.

Cliente MCP

Un componente adentro del host que mantiene la conexión con un servidor y le trae el contexto.

Servidor MCP

Un programa que ofrece contexto y herramientas. El de GitHub, el de una base de datos, el de tu n8n.

Regla clave: el host crea un cliente por cada servidor, y cada cliente mantiene una conexión dedicada con el suyo. Si Codex está conectado a una base de datos y le sumás GitHub, crea un segundo cliente para GitHub.

Dos capas: el idioma y el medio

Capa de datos = el idioma

Qué se dice. Un protocolo basado en JSON-RPC: cómo se descubren las capacidades y cómo se piden las herramientas, los recursos y los prompts.

Capa de transporte = el medio

Por dónde se dice: cómo se establece la conexión y cómo se autoriza. Como lo mismo se puede decir por teléfono, por carta o por mail.

JSON-RPC 2.0: un estándar que usa otro estándar

MCP usa JSON-RPC 2.0 (Remote Procedure Call), un formato viejo y probado para decir «ejecutá esta función con estos parámetros y devolveme el resultado». MCP no inventó la rueda. Ya vieron APIs, webhooks y el HTTP Request: MCP es, en esencia, una API con un formato acordado por todos.

El cliente pide: «ejecutá la herramienta del clima» 
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "weather_current",
    "arguments": { "location": "Buenos Aires" }
  }
}
El servidor responde 
{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "resultType": "complete",
    "content": [{ "type": "text", "text": "Buenos Aires: 22°C, parcialmente nublado" }]
  }
}

La respuesta sigue la versión vigente de la especificación (2026-07-28), que suma el campo resultType. Verificado el 21 de octubre de 2026 en modelcontextprotocol.io.

Teoría · 6 · Los transportes

Lo que importa es dónde corre el servidor

No si la herramienta es propia o de terceros: un servidor local también puede conectarse a un servicio de internet.

Servidor local (stdio)Servidor remoto (Streamable HTTP)
Dónde correEn tu propia computadora.En un servidor en internet.
Cómo se comunicaEntrada y salida estándar entre programas de la misma máquina, sin red de por medio.HTTP, con tokens, claves o encabezados. MCP recomienda OAuth para autenticar.
A cuántos atiendeNormalmente a un solo cliente.Normalmente a muchos.
EjemploQue la IA lea y escriba archivos de tu PC.Sentry, GitHub, Notion… y tu n8n.

¿Local o remoto?

El transporte viejo por SSE está deprecado desde 2025: lo que hay que usar es Streamable HTTP. El servidor MCP de n8n es remoto, por HTTP, y es el que conectamos en la práctica.

Teoría · 7 · Las tres primitivas

Lo que distingue a cada una es quién la activa

PrimitivaQué esQuién la activaEjemplo
Tools (herramientas)Funciones que la IA puede invocar para actuar: operaciones con archivos, llamadas a APIs, consultas a bases de datos.El modelo decide cuándo usarlas.Crear un issue en GitHub, mandar un newsletter.
Resources (recursos)Fuentes de datos que dan contexto: archivos, registros, respuestas de APIs. Sólo lectura.La aplicación decide qué adjuntar.El esquema de la base de datos, un documento.

Ejemplo integrador: un servidor MCP de una base de datos puede exponer herramientas para consultarla, un recurso con su esquema y un prompt con ejemplos de cómo usar esas herramientas.

¿Tool, resource o prompt?

Lo que el cliente le ofrece al servidor: la elicitación

Permite que el servidor le pida a la persona un dato que falta o una confirmación antes de actuar. Probalo: pedí que se borren 500 registros.

En la versión vigente de la especificación, la elicitación es la única capacidad del cliente que sigue en pie: las otras dos que existían quedaron deprecadas. Verificado el 21 de octubre de 2026.

Teoría · 8 · n8n y MCP

n8n juega de los dos lados del enchufe

A la izquierda, una IA de afuera entra a n8n: n8n es el servidor. A la derecha, el agente de n8n sale a buscar herramientas de otros: n8n es el cliente. Tocá cada forma.

Claude, ChatGPT, Codexuna IA de afuera
→
n8ntu instancia
→
Notion, GitHub, otro n8nun servidor MCP externo

Regla simple: para crear o editar flujos desde Claude o tu agente de código, el servidor MCP de la instancia. Para exponer un flujo puntual como servidor MCP propio, el MCP Server Trigger.

Teoría · 9 · Seguridad y cierre

Tres reglas de oro antes de conectar cualquier cosa

1

Mínimo acceso necesario

En n8n hay que habilitar MCP para la instancia y después cada flujo por separado. Y todo cliente que conectes ve todos los flujos habilitados: no se separa por cliente.

2

Sólo servidores confiables

Un servidor MCP es código que actúa en tu nombre, y lo que devuelve el modelo lo toma como cierto.

3

Confirmación humana en lo irreversible

Borrar, enviar, pagar, publicar. Por el servidor de n8n, un cliente conectado también puede publicar un flujo.

Práctica 1

Conectar tu agente de código con n8n por MCP

El material de la clase lo hace con Codex. Los pasos son los mismos con Claude Code u OpenCode: cambia sólo el comando para conectar. Lo que importa es lo que viene después, los tres pedidos y lo que hay que revisar en cada respuesta.

1 · Habilitar el servidor MCP en n8n

  1. En n8n, Settings → Instance-level MCP y activá Enable MCP access. Hace falta ser dueño o administrador de la instancia.
  2. Copiá la URL del servidor. Termina en /mcp-server/http.
  3. Para cada flujo que el agente tenga que ver, prendé Available in MCP.
  4. Para autenticarte, OAuth es lo recomendado: el agente abre el navegador y vos aprobás. La alternativa es un token personal; si la usás, no lo pegues nunca en un chat ni en un archivo que se comparta.

Práctica 2 · n8n como servidor

MCP Server Trigger: tus herramientas, y nada más

Un disparador que convierte el flujo en un servidor MCP. Cualquier cliente MCP —Claude, Codex, ChatGPT u otro n8n— se conecta, ve qué herramientas ofrece y las usa.

Dos URLs

Una de prueba, que escucha mientras probás en el editor, y una de producción, que anda cuando publicás el flujo. Igual que el Webhook de la clase 8.

Las herramientas cuelgan del disparador

Nodos de n8n usados como herramienta (Data Table, Google Sheets, Gmail) o flujos enteros, con el nodo que llama a otro flujo.

Nombre y descripción

Es lo que lee la IA para decidir cuándo usar cada una, como en «La descripción decide».

Instrucciones del servidor

Un texto que el disparador le manda al cliente cuando se conecta. Los clientes que lo admiten lo suman a las instrucciones del modelo: es contexto, como en la clase 11.

Servidor de la instancia

La IA accede a n8n en general

  • Ve, crea y edita flujos.
  • Ve todos los flujos habilitados.
  • Se activa en la configuración.
MCP Server Trigger

La IA ve sólo lo que diseñaste

  • Las herramientas que colgaste del disparador.
  • Ningún otro flujo, ninguna credencial.
  • Es un flujo más, que publicás.

Práctica 2 · n8n como cliente

MCP Client Tool decide un agente. MCP Client no decide nadie

MCP Client Tool

Un sub-nodo del AI Agent que lo conecta con un servidor MCP externo. El agente descubre las herramientas y decide solo cuándo usarlas. Es el mismo agente de la clase 10, con una herramienta que trae muchas capacidades de golpe.

  1. En el AI Agent, + de Tool → MCP Client Tool.
  2. La URL del servidor MCP externo.
  3. La autenticación, si el servidor la pide.
  4. Qué herramientas exponer: todas, sólo algunas o todas menos algunas. Elegir sólo las necesarias evita que el agente se confunda.

MCP Client

Un nodo común que llama a una herramienta específica de un servidor MCP externo. No hay IA decidiendo: se ejecuta siempre, en el lugar del flujo donde lo pusiste.

  1. La URL del servidor MCP.
  2. La autenticación, si hace falta.
  3. La herramienta: n8n trae la lista del servidor y elegís una.
  4. Los parámetros, a mano o con expresiones, como en cualquier nodo.

Regla simple: si sabés de antemano qué hay que hacer, MCP Client. Predecible, como un HTTP Request. Si la decisión depende de lo que pida la persona, MCP Client Tool. Flexible, pero menos predecible.

MCP Client Tool o el nodo nativo de n8n

Querés que tu agente use Notion. Podés conectarle el nodo de Notion de n8n como herramienta, o un MCP Client Tool apuntando al servidor MCP oficial de Notion.

Nodo nativo

Un empleado que entrenaste vos

  • La integración la construye y mantiene n8n.
  • Configurás cada operación por separado.
  • Control fino: decidís exactamente qué puede hacer el agente.
  • Credenciales en n8n, como siempre.
MCP Client Tool

Un proveedor con su catálogo

  • Las herramientas las define y mantiene el proveedor.
  • Un solo nodo trae todas, y podés filtrar.
  • Si el proveedor suma funciones, aparecen solas.
  • Dependés de que ese servidor funcione y sea confiable, y con muchas herramientas el agente puede confundirse.

Nodo nativo cuando existe y cubre lo que necesitás: es lo más estable y controlado. MCP Client Tool cuando n8n no tiene nodo para esa herramienta, cuando al nodo le falta la operación, o cuando querés conectar tu propio servidor MCP, por ejemplo el de la tienda desde otro n8n.

Práctica 2 · Seguridad

Lo mismo de la teoría, nodo por nodo

Server Trigger

Siempre con autenticación. Exponé sólo las herramientas necesarias, con descripciones claras.

Client y Client Tool

Conectá sólo servidores oficiales o de confianza. Lo que devuelve un servidor MCP, el agente lo toma como válido.

Client Tool

Filtrá las herramientas. Si el agente sólo necesita leer, no le des las que borran o modifican.

Credenciales

Siempre en el gestor de credenciales de n8n, nunca escritas en el nodo.
